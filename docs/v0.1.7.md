# Familiar Desktop v0.1.7

A small bug patch for a shared-shell resource risk: a running app can no longer turn its app ID into a remote icon download.

Foreign app IDs now stay icon names. Familiar looks up valid names locally and uses a generic local icon when lookup fails or the ID looks like a URL or path. HTTP(S) and other network image sources are blocked in the resolver and in both image bindings, including fallback icons. Normal local files, theme providers and Qt resources still work. Window matching, pins and folder membership keep their original IDs.

This fixes the [icon-loading finding in marketplace #10985](https://github.com/omacom/omarchy-plugin-marketplace/issues/10985#issuecomment-6132511757), through [PR #96](https://github.com/tcballard/omarchy-plugin-familiar-desktop/pull/96). The clipboard correction from v0.1.6 remains included.

## Updating

Use Omarchy's plugin update flow. First-time installation remains:

```bash
omarchy plugin add https://github.com/tcballard/omarchy-plugin-familiar-desktop --enable
```

Complete the matching native setup inside Familiar when prompted. Personal settings, pins and folders are preserved.

## Compatibility and testing

Stable binaries remain Linux x86_64. ARM development bundles and native CI remain available; stable ARM binaries and physical ARM acceptance are not claimed. General, Windows and Mac layouts remain available.

The icon fix passed all four automated desktop smoke configurations, including Qt 6.11.2 / Quickshell 0.3.1 and Qt 6.12.0 / Quickshell 0.3.2 with Omarchy's official titlebar renderer. Regression coverage checks foreign IDs in running apps, pins and folders, rejected network lookup results, both image bindings and normal local rendering. These are automated results; this patch has no separate physical XPS acceptance report.

Older hosts retain the same reviewed Hyprland 0.56.2 private-renderer fallback and exact ABI documented in the [v0.1.6 notes](v0.1.6.md). Marketplace re-review remains separate from release publication. CLI attribution to shared terminal windows remains unresolved.
